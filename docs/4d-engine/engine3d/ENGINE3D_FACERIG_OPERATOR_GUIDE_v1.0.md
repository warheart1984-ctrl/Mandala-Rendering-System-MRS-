> **Drive-G-1:** In-repo `HumanFace*.glb` files are **fixtures** (low tris) unless an operator overwrites them with licensed production assets. This guide does not claim a 20k–40k sculpt ships in the repository.

## 1. Purpose

Define how operators upgrade face assets (GLB) without changing Engine3D APIs or code.

## 2. Asset Paths

Stable paths (MUST NOT change):

| Path | Role |
|------|------|
| `mrs/assets/human/HumanFaceNeutral.glb` | Neutral face mesh |
| `mrs/assets/human/HumanFaceRigged.glb` | Rigged mesh + bones + blendshapes |

## 3. Operator Workflow

1. Sculpt or import a production-quality neutral face mesh (target 20k–40k tris — see topology checklist).
2. Rig the mesh with required bones and blendshapes ([FACE_RIG_SCHEMA](./ENGINE3D_FACE_RIG_SCHEMA_v1.0.md)).
3. Export GLB files named `HumanFaceNeutral.glb` and `HumanFaceRigged.glb` (see Blender export preset).
4. Overwrite the repo fixtures at the paths above.
5. Validate: `cd mrs/packages/engine3d-core && npm run validate:face-glb -- ../../assets/human/HumanFaceRigged.glb`
6. Redeploy MRS; no API or engine changes required.

## 4. CI vs Production

| Context | Asset | Notes |
|---------|-------|--------|
| CI / demos | Low-tris **fixtures** | Regenerated by `npm run build:face-fixture` |
| Production | High-tris **operator** assets | Same filenames; overwrite fixtures |

Tests MUST NOT depend on polygon count. Validation fails only on missing required bone / blendshape names.

## 5. Invariants

- Asset filenames and paths remain constant.
- Rig structure (bone and blendshape **names**) remains stable.
- Engine3D and public APIs remain unchanged when assets are swapped.
- Soft-raster structure stills record `face_rig`, `face_asset`, and optional `face_rig_detail` / `face_pose` evidence — they do not invent photoreal skin.

## 6. Governed polish path (prepared)

Portrait polish expects Engine3D beauty PNG as the structure conditioning image, then optional refine, with RT4D limited to non-face background / lattice. Flux Shell / NIM safety internals are **not** claimed as enforced MRS code; treat black or masked polish outputs as operator pipeline diagnostics unless proven otherwise in-repo.

## 7. Optional override path (**declared**, not implemented)

A future `/operator-assets/human/` (or env-based) override directory is **declared** only. Today, production upgrades overwrite the stable paths under `mrs/assets/human/`. No in-repo loader resolves a separate operator-assets root.
